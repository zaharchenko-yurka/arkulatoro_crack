# DEV_NOTES — ceiling-segment-calc

## Мета й межі

Плагін відновлює одну криволінійну сторону контуру стелі за замірами:
`S` (початок) → точки `V1..V(m-1)` → `E` (кінець, фіксований кут).
Для кожної точки відомі:
- `d_i = |V_i − O|` — радіус від кута-опори `O`;
- `s_i = |V_i − V_{i-1}|` — хорда сегмента, `V_0 = S`.

`O` може бути кутом контуру або ручною точкою поза контуром (декоративний виріз).

## Прийняті рішення

1. **Окремий плагін** з префіксами `csc-` / `CSC_`, шорткод `[ceiling_segment]`.
2. **Єдине ядро** `assets/csc-core.js` замість окремих `glc-import.js` + `chain-solver.js` з плану. Причина: обидва модулі тісно пов’язані геометрією та експортом, а єдиний UMD-модуль повторює архітектуру `ceiling-contour-calc` (`ccc-core.js`) і легко тестується в Node.
3. **Координати `.glc` не дзеркаляться під час експорту.** У форматі Arkulator вони вже зберігаються в його екранній системі (конвертер DXF→GLC робить `y' = minY + maxY − y` лише один раз). Тому імпорт → розрахунок → експорт зберігає орієнтацію. Користувацьке «Віддзеркалити (Y)» — окрема операція над усіма вхідними координатами (контур, S/E, O), тому експортований `.glc` теж буде віддзеркаленим.
4. **Останній рядок таблиці = кут E.** Точка фіксується на куті E, а її `d`/`s` лишаються м’якими контролями (показуються в останньому рядку як `✓`/`⚠`).
5. **М’які обмеження.** Усі `d_i` та `s_i` — це спостереження з вагою `1/σ²`; кінці `S`, `E` — жорсткі. Це дозволяє «зсувати» сегменти при шумі, як просив користувач.
6. **Одна сторона за розрахунок.** Решта контуру береться з імпортованого `.glc` без змін.

## Алгоритм

### Імпорт `.glc`
- Декодування: `TextDecoder("windows-1251")`; ручний CP1251-декодер як fallback (Node/browser).
- Блоки: `POINTS`/`AnglePoint`, `OTRARCS` (`OtrArcHei idx, h`), `otrlist_`/`NPLine` (`PoBeg`, `PoEnd`, `ArcPoint`, `ArcHei`).
- Дуга відновлюється через три точки `start → ArcPoint → end`, тому знак сагіти й напрямок не залежать від конвенції файлу. Якщо `ArcPoint` немає — використовується `ArcHei` як зсув по лівій нормалі хорди.
- Береться перша кімната; попередження, якщо кімнат кілька.
- Перевіряється замкненість контуру; розрив > 1 мм — попередження.

### Решатель ланцюга
1. **Посів.** Для кожного вузла перетинаються два кола: `(V_{i-1}, s_i)` і `(O, d_i)`. Через шум кола можуть не перетинатися — тоді береться найближча точка (clamped). Двозначність (два перетини) знімається **beam search** (ширина 6) зі штрафом за різкий поворот і за невідповідність залишку шляху до `E`.
2. **Уточнення.** Гаусс–Ньютон (до 60 ітерацій, line search) для невідомих `V1..V_{m-1}` з фіксованими `S`, `E`. Цільова функція — сума квадратів відхилень `d_i` і `s_i`.
3. **Похибка положення.** `σ_pos = σ·sqrt(diag((JᵀJ)⁻¹))`; показується як `±N` у бейджі. Попередження — лише при екстремальних значеннях (`> max(50, 12σ)`).
4. **Статуси рядків.** `warn` при `|Δ| > max(3σ, 5 мм)`, `error` при `> max(6σ, 10 мм)`.

### Побудова ребер
- Між сусідніми точками ланцюга будується дуга за дотичними: дотична у внутрішньому вузлі — з описаного кола трьох сусідніх точок; на кінцях S/E — кут (злам), бо це реальні кути кімнати.
- Якщо `|α| < 0.02°` — відрізок; якщо `|α| > 120°` — обмежується (захист від поганих замірів).
- Решта ребер імпортованого контуру зберігається як є; вибрані ребра замінюються ланцюгом. Підтримується сторона, що «перетинає» початок списку вершин.

### Ручні правки
- Перетягування точки зберігає зсув у світових координатах (`state.offsets[row]`), який додається після розрахунку.
- Після зсувів **перераховуються залишки й попередження** (інакше статус міг казати «без помилок» при великих Δ).
- При перемиканні дзеркала `dy` усіх зсувів інвертується, щоб правка «переїхала» разом з контуром.
- Кнопка «Скинути правки» очищає `offsets`.

## Експорт
- **`.glc`**: блоки як у `ceiling-contour-calc`/`dxf-glc-converter`; координати — без додаткового дзеркалення; `ArcPoint = mid + leftNormal · sagitta`; `GVals A/D/I/J` рахуються з геометрії; `UID1`/`ZoneGUI1` — нові UUID.
- Кінець рядка `\r\n`, кодування **windows-1251**.
- **DXF R12**: `POLYLINE` + `VERTEX` з `42 bulge` для дуг.
- **SVG**: замкнений `path`, підписи точок і розмірів (опційно).

## Виявлені й виправлені під час розробки проблеми
1. `hidden` не працював для полів із `display: grid` — додано `.csc-root [hidden] { display: none !important; }`.
2. «Залиплий» drag: після подій без натиснутої кнопки / втрати pointer capture зсуви могли накопичуватися (аж до абсурдних значень). Додано:
   - завершення drag при `event.buttons === 0`;
   - ігнорування `pointermove` при розмірі SVG < 1 px або некоректному `view`;
   - обмеження зсувів ±100 000 мм;
   - обробник `lostpointercapture`.
3. Статус «без помилок» після ручних зсувів — тепер попередження перераховуються з фінальних залишків.
4. Дзеркало після ручних правок змінювало результат — тепер `dy` зсувів інвертується разом із дзеркалом.

## Відомі ризики та обмеження
- **Парсер `.glc` не перевірений у реальній Arkulator** (CAD недоступна). Перевірено на трьох файлах репозиторію та на зворотному парсингу власного експорту.
- **Перша кімната**: файли з кількома кімнатами не об’єднуються.
- **Вирізи `VIREZS`** ігноруються.
- **Тріангуляція O** не реалізована — координати вводяться вручну.
- **Шум і близькі до дотику кола** можуть давати великі `±` (показується в бейджах); це чесна оцінка, а не помилка.
- **`s` як хорда**: якщо замірник міряв по дузі, для малих радіусів можлива систематична похибка; для типових R > 800 мм вона < 0.5 мм.
- **Кількість точок**: замало точок (2 рядки) дає лише одну проміжну точку — крива буде грубою; для реальних робіт 6–12 точок.

## Що можна додати далі
- Імпорт координат O через тріангуляцію від двох кутів.
- Декілька кривих сторін за один розрахунок.
- Використання виміряних радіусів дуг (`R-xxxx` з ескізу) як додаткових обмежень.
- Автоматичне згладжування/спрощення ланцюга з допуском.
- Підтримка `VIREZS` (декоративні вирізи) як окремих контурів.
- Збереження оригінальної `UID1`/метаданих кімнати.
